Допустим у нас есть какие-то 2 канала, один работает с целочисленным типом данных, другой со строкой, создадим для них 2 горутины, где будет бесконечный цикл, в котором в канал записывается то или иное значение
```go
package main

import (
	"strconv"
	"time"
)

func main() {
	intCh := make(chan int)
	strCh := make(chan string)
	go func() {
		i := 1
		for {
			intCh <- i
			i++
			time.Sleep(100 * time.Microsecond)
		}
	}()
	
	go func() {
		i := 1
		for {
			strCh <- "hi" + strconv.Itoa(i)
			i++
			time.Sleep(100 * time.Microsecond)
		}
	}()
}
```

Нам с этих каналов надо как-то читать,можно просто создать бесконечный цикл, куда мы будет в переменные записывать значение из канала и потом выводить  

```go
for {
	number := <-intCh
	fmt.Println("intCh:", number)
	str := <-strCh
	fmt.Println("strCh:", str)
}
```

Но если допустим поставить задержку в одной из горутин 1 секкунду, то выполнение сильно замедлится, когда вторая горутина уже записала давно свое значение в канал

Для того,чтобы работать с каналами,когда туда что-то приходит, есть такой инструмент, как select{}
```go
select {
case number := <-intCh:
	fmt.Println("intCh:", number)
case str := <-strCh:
	fmt.Println("strCh:", str)
}
```
Чем-то похоже на switch, но тут кейсы уже связанные с записью или чтением из каналов, когда что-то к нам приходит в какой-то из каналов, мы работаем с этим каналом в первую очередь, если в другой,то с другим, то есть, select{} ждет тот кейс, который первый разблокируется
Мы судя по нашему примеру,получаем возможность разблокировки при записи в канал целых чисел или канал строк,при этом значения из каналов записываются в нужные переменные; короче, у нас идет параллельная запись в 2 канала и какой кейс разблокируется,(где будет вообще какое-то значение), тот и обрабатывается

## default
У конструкции select{} есть default, для чего она нужна? Он у нас выполняет какой-то функционал, если ни в одном из каналов ничего нет
```go
package main

import (
	"fmt"
	"time"
)

func main() {
	intCh := make(chan int)
	strCh := make(chan string)
	go func() {
		intCh <- 1
		time.Sleep(200 * time.Millisecond)
	}()
	go func() {
		strCh <- "hi"
		time.Sleep(100 * time.Millisecond)
	}()
	
	select {
	case number := <-intCh:
		fmt.Println("intCh:", number)
	case str := <-strCh:
		fmt.Println("strCh:", str)
	default:
		fmt.Println("Никакой канал не готов")
	}
}

// выведется "Никакой канал не готов", так как оба канала пустые
```

Кстати, в данном случае select{} выполнится всего 1 раз и завершится,вот в цикле он мог бесконечно работать, еще select блокирует ту горутину, в котором объявлен, и пока одно из его условий не будет выполнено, он не разблокируется, а прога отдельно от остальных потоков - тоже поток

В проге выше если выше селекта поставить задержку в 500мс, то понятное дело что-то в какой-то из каналов успеет записаться, и следовательно отработает какой-то рандомный кейс, а точнее какой быстрее

Если default не будет, то select{} будет ждать,пока какой-то из кейсов разблокируется

## Небольшой примерчик
Когда нам нужно слушать 2 и более канала?
Допустим мы пишем свою какую-то социальную сетку или мессенджер и мы одновременно хотим слушать сообщения от двух человек(как один нам может что-то написать,так и другой) , писать они будут с одной стороны канала,а мы слушать условно с другой 
В плане реализации, мы создаем структуру, где из полей автор и текст, далее 2 канала, 2 горутинки,где записываем в канал экземпляр Message, ну и далее цикл, где с каналов в переменные записываются какие-то значения и выводятся
```go
package main

import (
	"fmt"
	"time"
)

type Message struct {
	Author string
	Text string
}

func main() {
	messageChan1 := make(chan Message)
	messageChan2 := make(chan Message)
	go func() {
		for {
			messageChan1 <- Message{
				Author: "Друг1",
				Text: "Привет",
			}
			time.Sleep(10 * time.Second)
		}
	}()
	
	go func() {
		for {
			messageChan2 <- Message{
				Author: "Друг2",
				Text: "Как дела",
			}
			time.Sleep(100 * time.Millisecond)
		}
	}() 
	for {
		msg1 := <-messageChan1
		fmt.Println("Сообщение от:", msg1.Author, "Текст:", msg1.Text)
		msg2 := <-messageChan2
		fmt.Println("Сообщение от:", msg2.Author, "Текст:", msg2.Text)
	}
}
```
В плане вывода все также , выводятся подряд сообщения `"Сообщение от: Друг1 Текст: Привет"` и `"Сообщение от: Друг2 Текст: Как дела"`, но как и в первом примере,если повысить задержку для первого, скажем, до 10 секунд(типо отлучился на 10 сеунд), то появление сообщения  от второго надо будет еще долго ждать, хотя он его давно отправил
А теперь представим,что друг отлучился не на 10с, а на 1 день там, и мы целый день не сможем получать сообщения от второго друга, а так недльзя
Вот для этого select и нужен:
```go
select {
case msg1 := <-messageChan1:
	fmt.Println("Сообщение от:", msg1.Author, "Текст:", msg1.Text)
case msg2 := <-messageChan2:
	fmt.Println("Сообщение от:", msg2.Author, "Текст:", msg2.Text)
}
```
Теперь не смотря на то,что первый друг будет нам слать сообщения только раз в 10 секунд, мы сможем получать сообщения и от второго
Это один из кейсов использования select{}, есть еще какой-то другой,но о нем позже
