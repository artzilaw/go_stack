В чем сейчас основная проблема нашего приложения? А проблема в том,что вся информация насчет того,что у нас происходит остается в консольном выводе. Вот у нас пришел на хендлер HTTP запрос - мы вывели что-то в консоль, пришел еще один - опять вывели что-то в консоль. И получается,что клиенту как таковая информация после запроса не доходит и оно все остается на удаленном сервере, так как у клиента нет доступа к выводу из консоли. Как раз для передачи подобной информации и существуют статус коды и тело ответа.
Что такое тело ответа? Грубо говоря,то же самое,что и тело при http-запросе, но в виде ответа клиенту. Благодаря этому клиенты могут понять,как прошла операция. 

Так-то,мы уже работали с http-ответом, это делается через w.Write():
```go
func payHandler(w http.ResponseWriter, r *http.Request) {

	}
	httpRequestBodyString := string(httpRequestBody)
	paymentAmount, err := strconv.Atoi(httpRequestBodyString)

		fmt.Println(msg)
		_, err := w.Write([]byte(msg))
		if err != nil {
			fmt.Println("fail to write http response:", err)
		}
		return
	}
	mtx.Lock()
	if money-paymentAmount >= 0 {
		money -= paymentAmount
		msg := "Оплата прошла успешно:" + strconv.Itoa(money)
		_, err := w.Write([]byte(msg))
		if err != nil {
			fmt.Println(err)
		}
```

А что же такое статус код ответа? Если посмотреть в postman, там есть какоое-то число 200 при успешном запросе, это как раз статус код ответа. 
![[200_code.png]]

Тоесть, во время обработки запроса мы можем также отдавать статус код ответа, помимо тела ответа. Но зачем нужен статус код, если вся нужная информация итак дается в теле ответа? Потому если мы отправляем http-запрос с какой-т комады легче ориентироваться на статус код насколько успешно или неуспешно была произведена операция. И если запрос был успешен,то вернет ожидаемую информацию,а если нет, то текст какой-то ошибки

Допустим мы делаем куда-то какой-то запрос и в ответ приходит статус код 200(общепринятое обозначение того,что запрос успешно обработан) и раз код 200, то мы получаем в теле ответа нужную информацию. А если придет код например 500(ошибка сервера), а это значит,что у нас в теле ответа будет уже не ожидаемый ответ на запрос, а какой-то текст ошибки. Поэтому статус код и тело ответа идут единым целым,мы как сделаем запрос нп сервер по-любому получим помимо тела ответа еще и статус код.

Посмотрим на примере нашей программы, как оно работает. Если мы вместо целочисленного значения внесем что-то еще, то нам выскочит это:
![[http_wrong_200.png]]

Тоесть, при некорректном запросы мы получили код 200. Чтобы такого не происходило,надо обрабатывать статус код по этому методу: 
```go
w.WriteHeader(http.StatusInternalServerError) // вместо http.StatusInternalServerError может быть любой другой код
```

По нему мы как раз и передаем статус код,который надо вернуть(подробнее про каждый код тут: https://developer.mozilla.org/ru/docs/Web/HTTP/Reference/Status), вот пока отвлекаясь от видео еще статус коды в общем 
![[status_codes_common.png]]

Так вот,возвращаясь к примеру, надо в секцию, где мы обрабатываем ошибку прописать этот метод и передать ему нужный статус код(конкретно тут 500,так как такая ошибка только при ошибке сервера возникает)
```go
if err != nil {
	w.WriteHeader(http.StatusInternalServerError)
	
	msg := "err:" + err.Error()
	fmt.Println(msg)
	_, err := w.Write([]byte(msg))
	if err != nil {
	fmt.Println("fail to write http response:", err)
	}
	return
}
```

Далее,у нас идет секция,где мы обрабатываем перевод запроса клиента в  int, тут мы передаем статус код 400(Bad Request). Этот код означает,что пользователь ввел некорректный формат данных,тоесть ошибка со стороны клиента,так как со своей стороны мы запрос обработали.

```go
if err != nil {
	w.WriteHeader(http.StatusBadRequest)
	msg := "Fail to convert HTTP body to integer" + err.Error()
	fmt.Println(msg)
	_, err := w.Write([]byte(msg))
	if err != nil {
		fmt.Println("fail to write http response:", err)
	}
	return
}
```
