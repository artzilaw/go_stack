У нас предприятие,где работают шахтеры и почтальоны,шахтеры будут теперь в бесконечном цикле добывать уголь, причем добывать будет разное количество угля, уголь он будет приносить в пункт передачи угля, мы будем брать уголь с этого пункта и складировать его в переменную coal

Теперь про почтальонов, при запуске мы должны передавать им то письмо, которое он должен переносить,сам почстальон раз в секунду в бесконечном цикле будет нам переносить письма 

Что почтальоны,что шахтеры должны быть завязаны на каком-то контексте

как они  завершатся,мы в конце выведем за день добытый уголь и за день доставленные сообщения 

Для начала надо описать шахтера, опишем его как функцию, которая принимает канал, номер шахтера и сколько угля надо передать, тут ничегго интересного, просто запись в канал
```go
func Miner(ch chan<- int, n int, power int) {
	for {
		fmt.Println("Я шахтер номер", n, "начал добывать уголь")
		time.Sleep(1 * time.Second)
		fmt.Println("Я шахтер номер", n, "добыл уголь", power)
		
		ch <- power
		fmt.Println("Я шахтер номер", n, "передал уголь", power)
	}

}
```

Чтобы же отменить горутины, завязанные на шахтере,надо завязать их на контекст:
```go
func Miner(ctx context.Context, ch chan<- int, n int, power int) {
	for {
		select {
		case <-ctx.Done():
			fmt.Println("Я шахтер номер", n, "мой рабочий день закончен")
			return
		default:
			fmt.Println("Я шахтер номер", n, "начал добывать уголь")
			time.Sleep(1 * time.Second)
			fmt.Println("Я шахтер номер", n, "добыл уголь", power)
			
			ch <- power
			fmt.Println("Я шахтер номер", n, "передал уголь", power)
		}
	}
}
```

Тут по классике через селект смотрим, закончен ли контекст,если да,то мы из функции выходим и следовательно горутина завершается

далее надо как-то прописать логику, по которой мы будем запускать всех этих шахтеров,пока это выглядит так :
```go
func MinerPool(ctx context.Context, minerCount int) chan int {
	ch := make(chan int)
	var wg sync.WaitGroup
	
	for i := 1; i <= minerCount; i++ {
		wg.Add(1)
		go Miner(&wg, ctx, ch, i, i*10)
	}
	
	go func() {
		wg.Wait()
		close(ch)
	}()
	return ch
}
```

Что мы тут сделали? в качестве аргументов у нас выступает контекст(нужен просто чтобы передать его функции Miner()) и число шахтеров minerCount, возвращаем же мы канал,зачем канал возвращать? Чтобы мы могли читать его, в то время, пока туда записывают свои значения шахтеры, мы поэтому иницилизируем его в в теле функции,также нам надо дождаться того,чтобы шахтеры записали все в канал,перед тем, как его закрыть,за это отвечает WaitGroup, инициализируем её в функции и передаем по ссылке в Miner() (все же нам надо дождаться выполнения именно этой горутины)
А что означает конструкция ниже?
```go
go func() {
	wg.Wait()
	close(ch)
}()
```
Так как нам надо одновременно с записью в канал читать оттуда значения, мы должны запустить  `wg.Wait()` и `close(ch)` в отдельной горутине, так как без этого у нас тупо заблокается поток и при попытке параллельнрго чтения просто выскочит дедлок 

С шахтерами закончили,теперь почтальоны, там по сути ничего интересного, все то же самое, что описано выше 
```go
package postmain

  

import (

"context"

"fmt"

"sync"

"time"

)

  

func Postman(wg *sync.WaitGroup, ctx context.Context, ch chan<- string, n int, mail string) {
	defer wg.Done()
	for {
		select {
		case <-ctx.Done():
			fmt.Println("Я почтальон номер", n, "мой рабочий день закончен")
			return
		default:
			fmt.Println("Я почтальон номер", n, "взял письмо")
			time.Sleep(1 * time.Second)
			fmt.Println("Я почтальон номре", n, "донес письмо до почты: ", mail)  
			ch <- mail
			fmt.Println("Я почтальон номер", n, "передал письмо: ", mail)
		}
	}
}

  

}

  

func PostmanPool(ctx context.Context, postmanCount int) <-chan string {
	ch := make(chan string)
	var wg sync.WaitGroup
	
	for i := 1; i <= postmanCount; i++ {
		wg.Add(1)
		go Postman(&wg, ctx, ch, i, postmanToMail(i))
	}
	go func() {
		wg.Wait()
		close(ch)
	}()
	return ch
}
```

Единственное,что интересно, это генерация сообщений, автор ее сделал через функцию, где в качестве аргумента у нас стоит номер почтальона, эта функция возвращает строку, внутри функции объявили мапу, где по числовому значению доступна какая-то строка, далее возвращаем строку по ключу(`ptm[postmanNumber]`), но через ok смотрим,есть ли такое значени(это получается 4 и дальше письмо), если нет, то идет текст по умолчанию, в коде это выглядит так:
```go
func postmanToMail(postmanNumber int) string {
	ptm := map[int]string{
		1: "От пахана Шафи",
		2: "От Абукураха из Кореи",
		3: "Информация из РОВД на вокзале в Дербенте",
	}
	mail, ok := ptm[postmanNumber]
	if !ok {
		return "Письмо от военкомата"
	}
	return mail
}
```

Теперь перейдем к описанию этого всего  в main, я сейчас вставлю просто код, и потом объясню что сделал
 ```go
 package main

import (
"context"
"fmt"
"hw/miner"
"hw/postmain"
"sync"
"sync/atomic"
"time"
)

func main() {
	var coal atomic.Int64
	var mails []string
	
	var mtx sync.Mutex
	
	minerContext, minerCancel := context.WithCancel(context.Background())
	
	postmanContext, postmanCancel := context.WithCancel(context.Background())
	
	go func() {
		time.Sleep(3 * time.Second)
		postmanCancel()
	}()
	
	go func() {
		time.Sleep(6 * time.Second)
		minerCancel()
	}()
	coalTransferPoint := miner.MinerPool(minerContext, 300)
	mailTransferPoint := postmain.PostmanPool(postmanContext, 300)
	
	var wg sync.WaitGroup
	wg.Add(1)
	go func() {
		defer wg.Done()
		for v := range coalTransferPoint {
			coal.Add(int64(v))
		}
	}()
	
	wg.Add(1)
	go func() {
		defer wg.Done()
		for v := range mailTransferPoint {
		mtx.Lock()
		mails = append(mails, v)
		mtx.Unlock()
		}
	}()
	
	wg.Wait()
	fmt.Println("Всего угля добыто:", coal.Load())
	
	mtx.Lock()
	fmt.Println("Всего писем доставлено:", len(mails))
	mtx.Unlock()
}
 ```

 Объявляем переменные, куда будем складывать данные из каналов,  переменную, которая отвечает за уголь объявил как `atomic.Int64`, так как к ней имеет доступ как main горутина, так и горутина для записи значений из каналов туда, далее определяем контексты для шахтера  и почтальона, они друг от друга не зависят, хоть оба и имеют доступ к background контекстук. После всего этого я запускаю еще 2 горутины, где контексты отменяются,чтобы почтальоны и щахтеры закончили работать. Далее объявляются 2 канала, куда передаются функции для того,чтобы запустить шахтеров(как мы помним,под капотом эти функции вызывают  горутины Miner() и Postman() ). После, так как нам нужно параллельно с тем,что шахтеры и почтальоны  работают записывать в переменные значения, которые они закинули в свои каналы, это мы делаем через горутины,чтобы программа читала данные не только их одного канала, но чтобы они раньше времени не завершились,привязываем к waitgroup. В самих горутинах  для coal делаем добавление по методу atomic, а для добавления письма в слайс мы берем блокировку по мьютексу, это все делаем опять же потому что эти переменные имеют доступ еще и к main горутине, помимо горутин для записи(но в случае с mails мы еще и читаем  значение из main горутины )
