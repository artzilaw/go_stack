
У нас есть такой код:
```go
package main

import "net/http"
func handler(w http.ResponseWriter, r *http.Request) {

}
func main() {
	http.HandleFunc("", handler)
}
```

Что означает этот код? У нас есть функция `http.HandleFunc()`, в качестве первого аргумента у нас какой-то patern string(ниже объясню что это), а качестве второго какую-то функцию.  Если в vs code нажать на Tab, то автоматически запишется анонимная функция, с сигнатурой `(w http.ResponseWriter, r *http.Request)`(вынесли в отдельную функцию)

Так вот, `http.HandleFunc()` говорит о том,что мы будем делать какое сетевое взаимодейсвие , тоесть мы будем принимать какое-то входяще подключение и обрабатывать его в функции handler. 

Теперь разберемся,что у нас есть в handler. У нас есть некий  `w http.ResponseWriter` , он нужен для того, чтобы на входящие сетевые запросы, мы могли писать сетевые ответы. У него есть, например, метод `w.Write()`,  принимает он в себя некий []byte и возвращает целочисленное число и ошибку. Пока не особо понятно,что он в себя принимает, но сам по себе метод Write() записывает какую-то информацию в http ответ

Допустим с `w http.ResponseWriter` разобрались, но у нас также есть `r *http.Request`. Вот `r *http.Request` представляет из себя ту информацию,что пришла к нам от клиента . 

Пусть у нас при посылании http- запроса возвращается "hello world". Так как  метод принамает только []bytes, мы переводим строку в []bytes. Сам метод возвращает значение int и error. Значение int зачастую бывает никому не нужно, поэтому обрабатываем только ошибку, в коде это выглядит так:
```go
func handler(w http.ResponseWriter, r *http.Request) {
	str := "Hello world"
	b := []byte(str)
	_, err := w.Write(b)
	if err != nil {
		fmt.Println("Во время записи HTTP ответа произошла ошибка", err.Error())
	} else {
		fmt.Println("Я корректно обработал HTTP запрос")
	}
}
```

Но запустив программу в нынешнем виде выскочит паника. Почему так? А потому что перое значение `http.HandleFunc()` указано неправильно, а точнее патерн указан неправильно.

Сам из себя патерн представляет составляющую HTTP запроса. Тоесть, помимо домена,ip-адреса и порта должен быть указан еще и патерн. 
Представим,что нам надо будет создавать приложение посложнее и нам нужно будет несколько хендлеров, а не один. Вернемся к тому же примеру сбербанка, у нас допустим будет еще хендлер для оплаты, а еще хендлер для отмены оплат. Но как во время HTTP запроса указать,какое именно действие  хочу совершить, для этого и создан патерн. 

Вот представим,что дошли мы по итогу с клиента до нашего в сервиса, в сервисе надо уже будет выбирать через запросы,что мы хотим сделать(оплатить, отменить оплату и тд.). Не писать же  под отдельный хендлер отдельное приложение, с выделенным под него портом, хендлеров может быть сотни. 

Для примера, у нас нами написаный хендлер для отправки ответа клиенту обрабатывается по патерну `/default`, а наши хендлеры для для оплаты и отмены оплаты по патернам `/pay` и `/cansel`. И получается мы сказали прилоджению через пакет http,что если к нам придут по тому или иному патерну, надо вызвать тот или иной хендлер.  

```go
package main

  

import (

"fmt"

"net/http"

)

  

func payHandler(w http.ResponseWriter, r *http.Request) {

str := "Новый платеж обработан"

b := []byte(str)

_, err := w.Write(b)

if err != nil {

fmt.Println("Во время записи HTTP ответа произошла ошибка", err.Error())

} else {

fmt.Println("Я корректно совершил оплату")

}

}

  

func canselHandler(w http.ResponseWriter, r *http.Request) {
	str := "Оплата отменена"
	b := []byte(str)
	_, err := w.Write(b)
	if err != nil {
		fmt.Println("Во время записи HTTP ответа произошла ошибка", err.Error())
	} else {
		fmt.Println("Я корректно отменил оплату")
	}
}

func handler(w http.ResponseWriter, r *http.Request) {
	str := "Hello world"
	b := []byte(str)
	_, err := w.Write(b)
	if err != nil {
		fmt.Println("Во время записи HTTP ответа произошла ошибка", err.Error())
	} else {
		fmt.Println("Я корректно обработал HTTP запрос")
	}
}

func main() {
	http.HandleFunc("/default", handler)
	http.HandleFunc("/pay", payHandler)
	http.HandleFunc("/cansel", canselHandler)
}
```

Но даже так не запустится HTTP сервер, так как мы лишь описали работу хендлеров. Нам надо для этого вызвать следующую функцию: 
`http.ListenAndServe()`. Она запускает http-сервер и блокирует программу  на строчке, где эта функция объявлена. Принимает она адрес типа string(как я понял ip-адрес с портом), в качестве второго аргумента выступает handler, но это нужно для более тонкой настройке и об этом потом, поэтому просто ставим nil. Сама функция возвращает ошибку

```go
err := http.ListenAndServe(":9091", nil)
if err != nil {
	fmt.Println("Произошла ошибка", err.Error())
}
```

Вот теперь программа запустилась и мы можем обрабатывать запросы через postman. Построим наш запрос: возьмем домен/ip-адрес, порт и патерн и сделаем запрос серверу через postman.

Вот мы и сделали запрос по патерну `/default`,  и он нам действительно вернул то,что мы ожидаем(Hello world). С остальными патернами также. 

Еще хендлеры можно регистрировать на пустой патерн. Нам не обезательно везде писать что-то типо "/слово", можно просто указать "/".  Такой патерн называется корневым патерном, часто импользуется при заходе на главную страницу сервиса(пример: "youtube.com/" )
```go
package main

import (
	"fmt"
	"net/http"
)

func handler(w http.ResponseWriter, r *http.Request) {
	_, err := w.Write([]byte("Hello, World!"))
	if err != nil {
		fmt.Println("err:", err.Error())
		return
	}
	fmt.Println("Хендлер обработан успешно")
}

func main() {
	http.HandleFunc("/", handler)
	err := http.ListenAndServe(":9091", nil)
	if err != nil {
		fmt.Println("err:", err.Error())
	}
}
```

Ну и еще у нас каждый раз,когда мы делаем запрос нашему бекенд приложении, у нас под капотом запускается горутина. Для примера напишем еще один хендлер, где у нас при запросе к нему через эндпоинт будет time.Sleep(5 * time.Second). 

```go
func handlerSleep(w http.ResponseWriter, r *http.Request) {
	time.Sleep(5 * time.Second)
	_, err := w.Write([]byte("HTTP request"))
	if err != nil {
		fmt.Println("err:", err.Error())
		return
	}
	fmt.Println("Хендлер обработан успешно")
}
```

В main опишем взаимодействие через эндпоинт так : `http.HandleFunc("/sleep", handlerSleep)`. И при запросе по этому эндпоинту у нас реально будет ожидаение 5 секунд перед ответом. 
![[http_request_sleep.png]]
И если бы у нас была последовательная обработка,пользователь бы ждал 5 секунд перед тем,как отправить свой запрос, проверить это можно через интерфейс postman, который позволяет сразу отправить 2 запроса. Иллюстрацию вставить проблематично будет, поэтому просто скажу,что если 2 `/sleep` запроса отправить  одновременно, оба придут через 5 секунд,а не первй через 5, а второй через 10
