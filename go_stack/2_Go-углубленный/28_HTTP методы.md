Метод можно подсмотреть в postman около поля ввода для http-запроса. 
![[http_methods.png]]
Как мы видим,тут есть методы GET,POST,PUT и тд. Что же это все такое?
Каждый раз,когда мы посылаем запрос,мы вместе с телом запроса, хеддеров в запросе отправляем еще и метод запроса. 

На примере payHandler() можно посмотреть,какой запрос к нам пришел через r.Method и вывода его в консоль, и при посылании запроса выведется это:
```go
GET // вот как раз наш метод запроса
Оплата прошла успешно:900
```

Если через постман выбрать условно метод POST, то и в консоли он выведется, как и с любым другим методом.Но зачем он нужен то? 
Как я понял, для разделения логики, разные методы несут разные цели, GET-получение данных, POST-создание, PUT/PATCH- изменить, DELETE - удалять. Но разделять логику можно и через эндпоинты, по которому мы можем обратиться к хендлеру.

Но со слов автора, в комерческой разработке на эти методы кладется откровенно говоря болт,  и все обрабатывается в каком-нибудь POST или какой там у них метод по-умолчанию в Postman. Но все же знать надо как минимум для собесов.

Но пока рассмотрим со стороны того,что они важны. Задумывалось изначально это как сигнал того,что конкретно пользователь хочет сделать. К примеру есть пользователь указал метод GET, то он хочет получить какие-то ресурсы с нашего backend сервера. Если выбирается метод POST, это говорит о том,что я хочу создать какой-т ресурс, какое-то новое сообщение.  Если метод PATCH- то изменить уже существующий ресурс на сервере(в случае условного мессенджера- отредактировать уже существующее сообщение). Если DELETE,то что-то удалить. 

Но одно дело мало отправлять с условного Postman запрос с нужным методом, нужно еще и на серваке это все обрабатывать.Допустим,в payHandler() мы меняем уже существующее количество денег,значит мы должны обрабатывать его через метод PATCH, обработать это можно так:
```go
if r.Method != http.MethodPatch {
	w.WriteHeader(http.StatusMethodNotAllowed) 
	return
}
```

Мы вернули код ответа, который как раз связан с выбором неправильного метода(405) и завершили обработку хендлера. 
![[wrong_method_code.png]]

Тоесть,теперь нам надо осознанно со стороны клиента выбрать метод PATCH,отдавая себе осознанно отчет в том,что мы хотим на этом сервере что-то поменять. Таким образом,надо на сервере ставить проверки, того,какой метод отправляется.

Можно обойтись и без этого в теории,но лучше учитывать методы.
