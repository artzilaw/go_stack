Эффективность алгоритма оценивается по затраченным ресурсам(пространственная стложность) и по затраченному времени(временная сложность),причем и то,и то  оценивается как O(n). 
O(n) показывает как растет функция с ростом входных данных или колличества операций. 
Ниже самые частовстречаемые функции
![[func_complexity.png]]

1) константная,когда нет никаких циклов,чисто операции над какими-то отдельными данными. 
2) логарифмическая, о ней потом(когда у нас делится еа 2 исходный объем данных)
3)  Линейная,когда обрабатываем массив в цикле
4)  Квадратичная - это цикл в цикле, на вход поступает массив из десяти элементов, идет обработка в одном цикле,потом во внутреннем цикле
5) Кубическа - цикл x3
6) Факториальная- самая быстрорастущая функция

А вот примеры в коде: 
Константная :
```go
var sum int
a:= sum + 10
b:= a+4 // операции 3,O(3) -> O(1), хоть операции и 3, но при оценке сложности это все отбрасывается
```
Линейная:
```go
var l []int = []int{1, 2, 3, 4, 5}
var sum int
for i := 0; i < len(l); i++ {
	sum += l[i]
}
fmt.Println(sum) // n=5(размер входного массива); временная сложность n операций O(n); пространственная сложность = размеру массива + константа sum O(n)
```
Логарифмическая:
Получатся,когда мы какой-то набор данных делим на 2 и работаем только с оставшейся половиной 
![[algs_log.png]]
Квадратичная:
```go
var l []int = []int{1, 2, 3, 4, 5}

for i := 0; i < len(l); i++ {
	for j := 0; j < len(l); j++ {
	//
	}
}  // если у нас 2 массива разной длины,то будет O(k*m), где m и k- размеры массивов
```

Факториальная:
Она растет просто с невероятной скорость, и даже при небольших данных там значения функции будут просто гигантскими


Ну и еще повторюсь,что сложность не отображает точное кол-во операций, она показывает,как растет функция с ростом входных данных. 

Линейную сложность дает не только цикл,ее еще дает рекурсия(функция,вызываюзая сама себя). Вызов такой функции попадает в стек вызовов и под каждый вызов выделяется память(место). Поэтому и линейная сложность.
